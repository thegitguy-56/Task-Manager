### Why Did We Code It This Way?

- **Flask** was chosen for its simplicity and flexibility for small-to-medium web apps.
- **Jinja2 templates** allow dynamic content rendering and code reuse (base.html, partials).
- **Bootstrap** ensures a modern, responsive UI with minimal custom CSS.
- **Separation of concerns**: Backend handles logic/data, frontend handles presentation.
- **Modular structure**: Templates, static files, and models are organized for maintainability.

### How Are Frontend and Backend Connected?

- Flask routes in app.py map URLs to Python functions.
- These functions process requests, interact with the database (via models.py), and render HTML templates with dynamic data.
- Templates use Jinja2 syntax ({{ ... }}) to insert backend data into HTML.
- Forms in the frontend send POST requests to backend routes for actions like login, register, create/edit tasks.
- Static files (CSS) are linked in templates for styling.
- Partials are included in main templates for reusable UI elements.

### Example Flow

1. User visits /login → Flask route renders login.html.
2. User submits login form → POST request to /login route.
3. Backend validates credentials, sets session, redirects to /dashboard.
4. Dashboard displays tasks, teams, etc., using data passed from backend to dashboard.html.
5. User creates a task via a modal (partial), which sends data to a backend route to save in the database.
